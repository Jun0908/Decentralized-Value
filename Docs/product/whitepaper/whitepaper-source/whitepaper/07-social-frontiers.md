# 7. Social Design Explorations

{% hint style="warning" %}
**Design Exploration / Not Current Implementation**

This chapter does not describe implemented arenas or proven public policies. It explores the value tensions, Hard Constraints, and Value Pools that could arise if Value Decentralization were applied to different social domains.
{% endhint %}

The purpose is not to automate the selection of one correct policy. It is to make visible which value judgment was applied, within which context, to which evidence, by whose budget, and under which rule.

## 7.1 Humanitarian Aid

Simplifying eligibility checks can deliver aid faster, but may reduce resistance to fraud or duplicate claims. Strict screening can increase precision while delaying people who lost their documents, are displaced, or lack digital access.

| Design element | Example |
| --- | --- |
| Value Tension | delivery speed, coverage, fraud resistance, privacy |
| Hard Constraint | total budget, minimum emergency aid, appeal, data protection |
| Artifact | universal grant, staged aid, needs-aware distribution |
| Possible Value Pools | Rapid Relief, Vulnerable Households, Auditability |

## 7.2 Public Procurement

Concentrating procurement with the cheapest supplier may reduce short-term cost while creating a single point of failure during bankruptcy, disaster, or cyberattack. Diversifying suppliers may improve resilience while increasing cost.

| Design element | Example |
| --- | --- |
| Value Tension | procurement cost, supplier diversity, failure resilience |
| Hard Constraint | quality, legal eligibility, delivery capacity, audit trail |
| Artifact | single supplier, equal split, resilient lots |
| Possible Value Pools | Taxpayer Efficiency, Continuity, Local Suppliers |

## 7.3 Platform Dispatch

Optimizing only for the fastest customer arrival may concentrate work among a subset of workers or locations. Optimizing only for equal allocation may increase travel distance and waiting time.

| Design element | Example |
| --- | --- |
| Value Tension | customer speed, worker income stability, geographic coverage |
| Hard Constraint | minimum pay, rest, dangerous-route prohibition, appeal |
| Artifact | nearest-first, rotation, floor-aware dispatch |
| Possible Value Pools | Fast Service, Worker Stability, Regional Access |

## 7.4 Energy Justice

Dynamic pricing can reduce peak demand, but may concentrate costs on households that cannot easily change when they consume energy, including people using home medical equipment, older residents, and people living in poorly insulated housing.

| Design element | Example |
| --- | --- |
| Value Tension | peak reduction, household cost, comfort, carbon |
| Hard Constraint | safe temperature, medical power, opt-out, privacy |
| Artifact | dynamic price, flat support, protected flexibility |
| Possible Value Pools | Grid Stability, Low-income Protection, Carbon Reduction |

## 7.5 Emergency Coverage

Concentrating emergency resources in high-demand urban centers may improve average response time while worsening the worst response times in low-density regions.

| Design element | Example |
| --- | --- |
| Value Tension | median response time, worst-region response, idle capacity |
| Hard Constraint | severity priority, vehicle capacity, hospital capacity |
| Artifact | nearest dispatch, forecast placement, regional floor |
| Possible Value Pools | Citywide Speed, Rural Coverage, Critical Care |

## 7.6 Social Housing

Maximizing tenant turnover may provide housing to people on waiting lists more quickly, while disrupting the schools, care relationships, and communities of existing tenants.

| Design element | Example |
| --- | --- |
| Value Tension | waiting time, housing stability, community continuity |
| Hard Constraint | non-discrimination, accessibility, appeal, transition period |
| Artifact | strict turnover, permanent tenancy, income-indexed stability |
| Possible Value Pools | Urgent Access, Family Stability, Mixed Communities |

## 7.7 Conditions for moving from exploration to evidence

Advancing any of these ideas from a design exploration into social implementation would require at least:

- participatory design of metrics and constraints with affected communities;
- dataset provenance and privacy review;
- monitoring of unmeasured negative externalities;
- explicit separation of simulation and operational evidence;
- independent reproduction;
- appeal and dispute procedures;
- public authority over rule changes; and
- management of conflicts of interest between Value Pool funders and evaluators.

Whenever numbers are presented, they must be labeled as an Illustrative Assumption, Simulation Result, or Observed Data.
